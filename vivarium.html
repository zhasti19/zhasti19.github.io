Vivarium Simulator

A simplified multi-scale simulation framework for Synthetic Biology

What is Vivarium?

Vivarium is an open-source framework for building and connecting biological simulations. The key idea is composability: small, focused simulations (Processes) read and write named variables through Ports, and those variables are stored in shared Stores. Groups of Processes and Stores form Compartments (analogous to a cell or organelle), and a top-level Simulation orchestrates multiple Compartments—each running at its own time step.

This page presents a simplified JavaScript implementation of those concepts together with three interactive example simulations you can run directly in your browser.

🗄️ Store

Holds named state variables (e.g. population, ATP) and records their history at every global time step.

new Store({ population: 10, nutrients: 1000 })

⚙️ Process

Computes updates to store variables. Each Process has its own time step and fires only when enough simulated time has accumulated.

new Process('Growth', ports, timestep, updateFn)

🔌 Port

A named connection that maps a logical port (used inside the Process) to a specific Store inside the same Compartment. Ports decouple logic from storage layout.

ports = { cell: 'cellStore' }

📦 Compartment

Groups Stores and Processes together. Analogous to a cell or organelle—a self-contained simulation unit with its own internal state.

new Compartment(name, stores, processes)

🌐 Simulation

Top-level orchestrator. Advances every Compartment by a global Δt and lets each Process fire at whatever internal rate it needs.

new Simulation(compartments, dt)

How to Use the Framework

The full source is in vivarium.js. Two API styles are available.

API 1 – Simulation (flat stores, function-based processes)

// 1. Create a Store with named variables
const myStore = new Store({ glucose: 200, ATP: 10 });

// 2. Define a Process with a port mapping and its own time step
const glycolysis = new Process(
  'Glycolysis',
  { metabolites: 'myStore' },  // port → store name
  0.25,                         // fires every 0.25 time units
  (portState, dt) => {
    const { glucose, ATP } = portState.metabolites;
    return { metabolites: { glucose: -0.5 * dt, ATP: +1.0 * dt } };
  }
);

// 3. Bundle into a Compartment
const cell = new Compartment('Cell', { myStore }, [glycolysis]);

// 4. Run inside a Simulation (global dt = 0.1)
const sim = new Simulation({ cell }, 0.1);
sim.run(50);   // 50 time units

// 5. Read history from the store
console.log(myStore.history.ATP);   // array of ATP values over time

API 2 – Vivarium (hierarchical path-based store, class-based processes)

// 1. Subclass SimProcess – override next() with your dynamics
class CellGrowth extends SimProcess {
  constructor() {
    super({
      name: 'CellGrowth',
      ports: {
        volume: ['cell', 'volume'],      // port name → path in HierarchicalStore
        atp:    ['metabolism', 'atp'],
      },
      timeStep: 1.0                      // fires every 1.0 time unit
    });
  }

  next(inputs, dt) {
    const mu = 0.015 * inputs.atp / (1 + inputs.atp);  // Monod kinetics
    return { volume: inputs.volume * (1 + mu * dt) };   // return updated ports
  }
}

// 2. Compose with Vivarium (event-driven: smallest next-timestep wins)
const sim = new Vivarium({
  state: {
    cell:       { volume: 1.0 },
    metabolism: { atp: 2.0, glucose: 10.0, lactate: 0.0 },
  },
  processes: [new CellGrowth(), /* …more processes at their own time steps */],
  trackPaths: [
    ['cell', 'volume'],
    ['metabolism', 'atp'],
  ],
});

// 3. Run and inspect
const history = sim.run(60);    // simulate 60 time units
console.log(history.time);              // [0, 1, 2, …, 60]
console.log(history['cell.volume']);    // [1.0, 1.01, …]
